# poPromtu

Инструмент для модерации видео перед загрузкой на YouTube: вставляете ссылку на видео,
получаете уникальную ссылку на модерацию, команда проверяющих (2 и больше) оставляет
правки с привязкой к таймкоду, вы видите их все в одном месте и отмечаете исправленные.

## Возможности

- Админка (закрыта паролем): добавление видео по ссылке/ID YouTube, генерация
  уникальной ссылки на модерацию, управление командой проверяющих.
- Страница модерации: встроенный YouTube-плеер, кнопка «взять текущее время видео»,
  выбор проверяющего из фиксированного списка, список всех оставленных правок.
- В админке — список правок по видео с отметкой «исправлено» / «вернуть в открытые».

## Запуск локально

Нужен Postgres (локально или в контейнере).

```bash
npm install
cp .env.example .env   # задайте ADMIN_PASSWORD, SESSION_SECRET и DATABASE_URL
npm start
```

Приложение поднимется на `http://localhost:3000`. Админка — `/admin`.
Таблицы в базе создаются автоматически при старте.

## Деплой на Render

В репозитории есть `render.yaml` — Render Blueprint, который сразу создаёт
веб-сервис и базу Postgres.

1. Запушьте репозиторий в GitHub (уже сделано).
2. На [render.com](https://render.com) → **New** → **Blueprint** → выберите
   этот репозиторий.
3. Render прочитает `render.yaml` и предложит создать:
   - веб-сервис `popromtu` (Node, free-план);
   - базу `popromtu-db` (Postgres, free-план), автоматически подключенную
     через переменную `DATABASE_URL`.
4. Перед деплоем Render попросит задать `ADMIN_PASSWORD` вручную (он не
   хранится в репозитории) — введите пароль для входа в `/admin`.
   `SESSION_SECRET` Render сгенерирует сам.
5. Нажмите **Apply** — через пару минут сервис будет доступен по адресу
   вида `https://popromtu.onrender.com`.

**Важно про free-план Render:**
- Бесплатный веб-сервис засыпает после ~15 минут без запросов и просыпается
  10–30 секунд при первом обращении — для внутреннего инструмента это обычно
  не критично.
- Бесплатная база Postgres на Render **удаляется через 30 дней**, если не
  перейти на платный план — для долгосрочного использования базу нужно будет
  апгрейднуть (Render заранее присылает предупреждение на почту).

Если Blueprint недоступен (например, региональные ограничения), сервис можно
создать вручную: **New → Web Service** из репозитория (Build command
`npm install`, Start command `npm start`) и **New → PostgreSQL**, а затем
вручную прописать `DATABASE_URL`, `ADMIN_PASSWORD`, `SESSION_SECRET` в Environment
веб-сервиса.

## Как пользоваться

1. Зайдите в `/admin`, добавьте в команду проверяющих (имена).
2. Вставьте ссылку на YouTube-видео и название — получите ссылку вида
   `/moderate/<slug>`.
3. Отправьте эту ссылку проверяющим — они выбирают своё имя из списка,
   ставят таймкод и пишут правку.
4. В админке на странице видео отмечайте правки исправленными по мере
   доработки видео.

# poPromtu Промо — объявления по группам и учёт заявок

Второй модуль в этом же приложении: `/promo`. Помогает вести рекламу нескольких
клиентов в локальных группах (Facebook, Одноклассники, Telegram, Viber) —
генерирует уникальные тексты объявлений, ведёт очередь публикаций, принимает
заявки и считает, сколько клиент должен за принятые.

## Почему полуавтомат, а не бот

Facebook закрыл публикацию в чужие группы через API в 2020 году, у Одноклассников
через API доступны только свои группы. Публикация ботом, который эмулирует
браузер, нарушает правила площадок и ведёт к блокировке аккаунта — а вместе с
ним теряется доступ ко всем группам.

Поэтому система берёт на себя всё, кроме последнего клика: подбирает группу,
собирает уникальный текст, подставляет картинку, следит за частотой публикаций
и ведёт историю. Человек нажимает «Скопировать текст» → «Открыть группу» →
вставляет → «Опубликовано». Это ~5 секунд на группу.

## Как устроена генерация текста

Объявление собирается из трёх блоков: **заголовок + основной текст + призыв
к действию**. Каждого блока может быть сколько угодно вариантов, система
перебирает их сочетания: 3 заголовка × 3 текста × 3 призыва = 27 разных
объявлений.

При планировании публикации для группы выбирается то сочетание, которое дольше
всего в ней не использовалось, — так один и тот же текст не попадает в группу
дважды подряд (за это площадки помечают аккаунт как спамный).

В текстах доступны подстановки: `{{city}}`, `{{phone}}`, `{{service}}`,
`{{name}}`, `{{price}}`, `{{link}}`.

`{{link}}` — особая: она подставляет ссылку на заявку **той группы**, куда идёт
публикация, и именно по ней потом видно, какая группа приносит обращения. Без
неё заявка придёт без источника, поэтому все шаблоны-примеры её содержат, а на
странице клиента показывается предупреждение, если часть вариантов её потеряла.

Кнопка «Загрузить готовый набор-пример» создаёт рабочий комплект шаблонов,
который можно отредактировать под себя.

## Учёт заявок

- **Лендинг** `/l/<токен>/<id группы>` — простая страница с формой. Своя ссылка
  на каждую группу, поэтому видно, откуда пришла заявка.
- **Вебхук** `POST /api/lead/<токен>` — приём заявок из n8n, Make или любой
  внешней формы. Тело: `{"phone": "...", "name": "...", "message": "...",
  "group_id": 1, "source": "..."}`.
- **Дубли** определяются по последним 8 цифрам номера (`069112233` и
  `+37369112233` — один человек) в пределах настроенного окна. Дубль
  сохраняется, помечается и тарифицируется по нулю.

## Два языка

У каждой группы указан язык (русский или румынский), и у каждого блока текста —
тоже. Сочетания собираются **только внутри одного языка**, поэтому русский
заголовок никогда не встретится с румынским текстом в одном объявлении. Если у
группы нет шаблонов на её языке, она пропускается при сборке очереди с явным
сообщением, а не молча.

Набор-пример загружается отдельно для каждого языка — румынский написан живым
языком, а не построчным переводом.

Названия, которые пишутся по-разному, задаются в настройках клиента отдельно:
услуга, город, имя и цена. «Тараклия» в русском объявлении и «Taraclia»
в румынском. Если румынское поле пустое, берётся основное.

Лендинг для заявок тоже переключается: человек из румынской группы видит форму,
подсказки и сообщения об ошибках на румынском.

## Картинки

Макеты можно загружать файлами — они хранятся в Postgres (`promo_images.data`),
а не на диске: диск на free-плане Render не переживает перезапуск сервиса.
Отдаются по `/img/<id>`, для скачивания — `/img/<id>?download=1`. Ограничения:
JPEG, PNG или WebP, до 5 МБ. Альтернатива — прямая ссылка на внешнее хранилище,
оба варианта работают одновременно.

## Уведомления в Telegram

При каждой новой заявке уходит сообщение с телефоном, именем, текстом
обращения, источником и ссылкой на кабинет. Дубли помечаются отдельно.

Настройка:

1. Создайте бота у [@BotFather](https://t.me/BotFather), получите токен.
2. Задайте на сервере `TELEGRAM_BOT_TOKEN`.
3. Напишите боту любое сообщение и откройте
   `https://api.telegram.org/bot<токен>/getUpdates` — нужное число лежит
   в `chat.id`.
4. Свой chat id пропишите в `TELEGRAM_ADMIN_CHAT_ID` (туда падают заявки всех
   клиентов), chat id клиента — в настройках клиента (он получает только свои).
5. Кнопка **Проверить связь** в настройках клиента отправляет тестовое
   сообщение и показывает причину, если не дошло.

Если `TELEGRAM_BOT_TOKEN` не задан, уведомления просто не отправляются —
на приём заявок это не влияет. Сбой Telegram тоже не роняет заявку: она
сохраняется, а причина недоставки пишется в лог сервиса.

## Акт за месяц

Со страницы заявок — ссылка **«Акт за период»**. Открывается готовый документ по
форме Приложения №3 к договору: шапка со ссылкой на договор, таблица услуг,
НДС, сумма прописью, справочная сводка, реестр заявок и подписи. Кнопка
**«Печать / Сохранить в PDF»** отдаёт его на печать — вёрстка под A4.

Что берётся из настроек клиента: номер и дата договора, валюта расчётов
(MDL/EUR/USD), ставка НДС, цена за принятую заявку. Наименование исполнителя —
из переменной окружения `AGENCY_NAME`. Незаполненные реквизиты печатаются
прочерками, чтобы вписать от руки.

**Принятой считается и заявка, по которой истёк срок возражения** — это п. 4.6
договора. В акте такие идут отдельной строкой «Принято по истечении срока
возражения», а в реестре помечаются «(п. 4.6)». То же правило действует на
странице заявок и в кабинете клиента, поэтому суммы везде совпадают.

## График заявок по дням

На странице заявок — столбчатый график за выбранный месяц: столбец на день,
внутри два сегмента, «принято» и «не принято». Дни без заявок остаются в ряду
пустыми: выкинуть их значило бы исказить картину времени.

Рисуется inline-SVG прямо на сервере, без библиотек графиков. Подсказка по
наведению — через `<title>`, поэтому работает и без JavaScript. Под графиком
есть развороты «Показать таблицей»: те же числа для тех, кому график не подходит.

Цвета взяты из проверенной палитры и прогнаны валидатором на различимость при
дальтонизме и на контраст с поверхностью — отдельно для светлой и тёмной темы.

## Выгрузки: Excel и PDF

Со страницы заявок — четыре ссылки: **Excel** и **PDF** за выбранный период
и за всё время.

**PDF** — реестр заявок на A4 в альбомной ориентации: шапка со сводкой, таблица
со всеми заявками, повторяющаяся шапка таблицы и нумерация «стр. N из M» на
каждой странице. Годится, чтобы приложить к акту или отдать на подпись.

Шрифт DejaVu встроен в файл (`assets/fonts`): стандартные шрифты PDF не содержат
кириллицы, а DejaVu покрывает и её, и румынские диакритики — заявки бывают на
обоих языках. PDF собирается библиотекой pdfkit, без headless-браузера: Chromium
не влез бы в free-план Render ни по диску, ни по памяти.

**Excel** — файл `.xlsx` с двумя листами:

- **Заявки** — дата, телефон, имя, сообщение, группа-источник, площадка, язык,
  канал, статус, отметка о приёмке по сроку, причина отказа, признак дубля и
  сумма. Закреплена шапка, включён автофильтр.
- **Сводка** — итоги за период и разбивка по источникам.

Телефон записывается **текстом**: иначе Excel считает `069112233` числом и
съедает ведущий ноль. Даты пишутся датами, суммы — числами, поэтому по ним
сразу работают формулы и сортировка.

Формируется настоящий `.xlsx`, а не CSV: CSV в русской локали Excel открывается
одной колонкой из-за разделителя и портит номера телефонов.

## Кабинет клиента

`/c/<токен>` — ссылка без пароля, которую можно дать клиенту. Он видит свои
заявки, статистику и сумму к оплате, может принять заявку или отклонить её —
но только по причине из закрытого списка и только в течение 48 часов. После
этого срока заявка считается принятой. Это повторяет порядок приёмки из
договора, чтобы споры решались правилами, а не перепиской.

## Как пользоваться

1. `/promo` → добавьте клиента (имя, услуга, город, телефон).
2. Вкладка **Настройки** — цена в объявлении, ваша цена за принятую заявку,
   сколько публикаций планировать за раз, окно дедупликации.
3. Вкладка **Группы** — добавьте местные группы со ссылками и минимальным
   интервалом между публикациями (по умолчанию раз в 7 дней).
4. Вкладка **Шаблоны** — загрузите набор-пример и отредактируйте под клиента.
5. Вкладка **Картинки** — загрузите макеты файлами (JPEG/PNG/WebP до 5 МБ)
   или добавьте прямыми ссылками, если они уже лежат в открытом хранилище.
6. **Очередь** → «Собрать очередь» → публикуйте и отмечайте.
7. **Заявки** — принимайте, отклоняйте, смотрите сумму за период и то,
   какие группы реально приносят обращения.
