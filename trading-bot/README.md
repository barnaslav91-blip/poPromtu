# trading-bot

Бот для торговли синтетическим индексом **Crash 900 Index** на [Deriv](https://deriv.com).
Отдельный проект внутри репозитория `poPromtu`, со своими зависимостями —
на основное Express-приложение никак не влияет.

**Два варианта, под разные платформы:**
- `src/` — Node.js, торгует через Deriv API напрямую (`DERIV_API_TOKEN`,
  DTrader/Multiplier-контракты). Описано ниже на этой странице.
- `mt5/` — советник на MQL5 для **Deriv MT5** (терминал MetaTrader). Если
  вы торгуете через MT5-аккаунт (Login ID/Server/Broker, как в терминале
  MetaTrader) — вам нужен именно он, см. `mt5/README.md`. Та же стратегия,
  другая платформа исполнения.

## Как устроена стратегия (Node/Deriv API версия)

Момент "краха" на Crash-индексах — случайное событие с фиксированной
вероятностью на тик, предсказать его нельзя (так задуман инструмент).
Поэтому бот не пытается угадать крах, а:

1. Определяет направление по EMA-тренду (EMA9 vs EMA21 на минутных свечах)
   **и** доле растущих/падающих тиков за скользящее окно
   (`TICK_DIRECTION_WINDOW` тиков): растущих заметно больше
   (`>= TICK_DIRECTION_UP_THRESHOLD`) — ищем long (MULTUP), падающих заметно
   больше (`<= TICK_DIRECTION_DOWN_THRESHOLD`) — ищем short (MULTDOWN). В
   "спокойной" зоне между порогами сделок нет вообще.
2. Подтверждает вход стохастиком (%K/%D по тем же свечам): для long — `%K >
   %D` и не в зоне перекупленности (`STOCH_OVERBOUGHT`), для short —
   симметрично `%K < %D` и не в зоне перепроданности (`STOCH_OVERSOLD`).
   Параметры стохастика калибруются отдельно под каждый инструмент, см. ниже.
3. Адаптирует размер стоп-лосса под текущую волатильность (ATR): шире стоп
   в неспокойном рынке, уже — в спокойном.
4. После обнаружения резкого падения тика (крах-событие) ставит паузу на
   `COOLDOWN_TICKS_AFTER_CRASH` тиков — не открывает новые позиции ни в
   какую сторону, пока цена не стабилизируется.
5. Ведёт трейлинг-стоп по ATR (`TRAIL_ATR_MULTIPLE`, chandelier exit): стоп
   подтягивается за пиком (long) или дном (short) цены с момента входа. На
   длинных безоткатных движениях (как на затяжном тренде) это фиксирует
   часть прибыли раньше, чем сработает выход по развороту EMA — бот не ждёт
   полного разворота, чтобы отдать весь набранный ход обратно. Изначально
   трейлинг шире жёсткого биржевого стопа и не мешает ему на самом входе.
6. Считает размер сделки как фиксированный % риска от баланса
   (`RISK_PER_TRADE_PCT`) — **без мартингейла**, ставка не растёт после
   проигрышей. Именно удвоение ставки после убытка — типичная причина
   слива депозита на этом инструменте.
7. Останавливает торговлю на день при достижении `MAX_DAILY_LOSS_PCT`.

**Про шорты (MULTDOWN):** Crash-индексы структурно дрейфуют вверх между
крахами — площадка так их и задумала. Short ловит локальные падающие
участки этого дрейфа, но играет против общей структурной тенденции
инструмента, в отличие от long. Это осознанное решение, а не встроенное
допущение стратегии — если не нужно, уберите `wantDown`-ветку в
`src/strategy.js` или задайте `TICK_DIRECTION_DOWN_THRESHOLD=-1` (доля
растущих тиков не может быть отрицательной — порог недостижим, шортов
не будет).

## Инструмент: Crash 900 или Crash 1000

Индекс задаётся в `.env` через `SYMBOL_DISPLAY_NAME` (по умолчанию
`Crash 900 Index`). Чтобы переключиться на `Crash 1000 Index`, поменяйте
значение на точное название инструмента и перекалибруйте стохастик (ниже) —
у индексов разная частота крахов (в среднем раз в ~900 и ~1000 тиков), а
значит и разный "шум" между ними, числа с одного индекса не переносятся на
другой напрямую. Откатиться назад — просто верните прежнее значение.

## Калибровка стохастика под конкретный индекс

```bash
npm run calibrate
```

Перебирает сетку параметров стохастика (`period`, `smoothK`, `smoothD`,
`overbought`) на исторических тиках *того инструмента, который сейчас задан
в `SYMBOL_DISPLAY_NAME`*, прогоняет каждую комбинацию через `npm run
backtest`-логику (сделки в обе стороны, long и short, как задаёт
направленческий фильтр) и печатает топ-10 по итоговому P&L (с win rate и
просадкой рядом, чтобы не выбрать вариант с 3 удачными сделками). Выбранную
комбинацию впишите в `.env` (`STOCH_PERIOD`, `STOCH_SMOOTH_K`,
`STOCH_SMOOTH_D`, `STOCH_OVERBOUGHT`) и перепроверьте `npm run backtest`.
`STOCH_OVERSOLD` и `TICK_DIRECTION_*` сетка не перебирает — подбираются
вручную через повторные прогоны `npm run backtest`, если нужна тонкая
настройка.

Торгуются мультипликаторные контракты (MULTUP/MULTDOWN, в зависимости от
направления сигнала) с жёстким `stop_loss`, выставленным на бирже — риск
на сделку известен заранее и не зависит от скорости реакции бота.

**Это не гарантия прибыли.** У синтетических индексов Deriv встроенное
преимущество площадки (house edge). Стратегия управляет риском и ловит
тренд, а не "обыгрывает" площадку.

## Настройка

Нужен аккаунт на [deriv.com](https://deriv.com) (подойдёт бесплатный) и:

1. `DERIV_APP_ID` — зарегистрируйте приложение на
   https://api.deriv.com/dashboard/ (Register application), возьмите App ID.
2. `DERIV_API_TOKEN` — Settings → API token на deriv.com. **Для старта
   создайте токен на демо-счёте** (переключитесь на демо в верхнем меню
   перед созданием токена) со скоупами `Read` и `Trade`.

```bash
cd trading-bot
npm install
cp .env.example .env   # впишите DERIV_APP_ID и DERIV_API_TOKEN
```

## Бэктест (сделать перед демо-торговлей)

Прогоняет стратегию на исторических тиках без реального счёта и без
токена (нужен только `DERIV_APP_ID`):

```bash
npm run backtest
```

Выведет число сделок, win rate, итоговый P&L и максимальную просадку на
виртуальном балансе 1000. Если просадка/статистика выглядят плохо —
меняйте параметры в `.env` (`RISK_PER_TRADE_PCT`,
`COOLDOWN_TICKS_AFTER_CRASH`) или пороги в `src/strategy.js` перед тем,
как переходить к демо-счёту.

## Демо-торговля

```bash
npm start
```

Бот подключится к Deriv, подпишется на тики Crash 900 Index и начнёт
торговать на счёте, привязанном к `DERIV_API_TOKEN`. Все сделки пишутся
в консоль и в `trades.log` (JSON lines). Остановить — `Ctrl+C`.

Убедитесь, что токен выпущен именно для **демо-счёта** — с реальным
токеном бот сразу начнёт торговать настоящими деньгами.

## Переход на реальный счёт

Осознанный отдельный шаг: создайте API-токен на реальном счёте и
подставьте в `.env`. Рекомендуется сначала не меньше нескольких недель
понаблюдать за демо-результатами и при необходимости снизить
`RISK_PER_TRADE_PCT`.
